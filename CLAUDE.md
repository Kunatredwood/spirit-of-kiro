## Project Overview

Spirit of Kiro is an infinite crafting workshop game where >95% of the code was written by prompting AI. This is a demo project showcasing best practices for AI engineering. The game features:

- **Infinite item generation** - Every item is unique, generated by AI with unique names, descriptions, damage values, and skills
- **Freeform crafting** - Items have skills/quirks that can be used on other items, with AI calculating outcomes (no hardcoded crafting recipes)
- **AI-powered appraisal** - Sell items to see what the AI thinks they're worth
- **Scale-optimized architecture** - Performance improves with more players through item reuse and vector-based image matching

## Architecture

### Three-Component System

1. **Game Client** (Vue.js 3)
   - Component-based UI with Vue Composition API
   - System-based architecture with independent systems communicating via events
   - Reactive state management using Pinia
   - Server-driven events via WebSocket feeding into frontend event system

2. **Game Server** (Bun + WebSocket)
   - WebSocket server for real-time bi-directional communication
   - Message-based handler architecture (see [server/handlers/](server/handlers/))
   - AWS Bedrock integration (Sonnet 4, Sonnet 3.7, Nova Pro) for item generation, crafting, and appraisal
   - DynamoDB for state persistence
   - Amazon Cognito for authentication

3. **Item Images Service** (separate, hosted)
   - Amazon Nova Canvas for image generation
   - Titan Text Embeddings v2 for vector embeddings
   - MemoryDB vector database for matching similar items to reuse images
   - S3 + CloudFront for image storage and delivery

### Client Systems

Located in [client/src/systems/](client/src/systems/):

- **Socket System** - WebSocket connection management and message routing
- **Game Object System** - Tracks all rendered game objects
- **Physics System** - Collision detection, movement, gravity, bounce, friction
- **Item System** - Item properties and synchronization
- **Inventory System** - Item pickup, drop, transfer between inventories
- **Persona System** - Player character data and customization
- **Preloader System** - Asset loading and progress tracking

### Server Architecture

- **Message Handlers** - Each handler in [server/handlers/](server/handlers/) processes a specific WebSocket message type
- **State Management** - Located in [server/state/](server/state/)
- **LLM Integration** - Located in [server/llm/](server/llm/)
- **Infrastructure as Code** - CloudFormation templates in [server/iac/](server/iac/)

Key message types documented in [docs/server-messages.md](docs/server-messages.md):
- Authentication: `signup`, `signin`
- Inventory: `list-inventory`, `move-item`, `discard-item`
- Items: `pull-item`, `use-skill`, `sell-item`
- Economy: `peek-discarded`, `buy-discarded`

## Development Commands

### Initial Setup

```bash
# Clone and install dependencies
git clone <repo-url>
bun install
cd client && bun install
cd ../server && bun install

# Deploy Cognito resources (required before first run)
./scripts/deploy-cognito.sh game-auth

# Bootstrap local DynamoDB tables (required before first run)
bun ./scripts/bootstrap-local-dynamodb.js
```

### Running Locally

**With Docker/Podman (recommended):**
```bash
# Start all services with hot reload
podman compose build && podman compose up --watch --remove-orphans --timeout 0 --force-recreate

# Bootstrap DynamoDB (first time only)
podman exec server mkdir -p /app/server/iac &&
podman cp scripts/bootstrap-local-dynamodb.js server:/app/ &&
podman cp server/iac/dynamodb.yml server:/app/server/iac/ &&
podman exec server bun run /app/bootstrap-local-dynamodb.js

# Fix time desync (if needed on system sleep/wake)
podman machine ssh sudo systemctl restart chronyd.service
```
(Replace `podman` with `docker` if using Docker Desktop)

**Without Docker:**
```bash
# Launch both client and server with single command
bun launch.ts

# OR launch separately:
cd client && bun run dev      # Client on http://localhost:5173
cd server && bun --watch server.ts  # Server on ws://localhost:8080
```

## Key Concepts

### AI-Driven Emergent Interactions

Unlike traditional games with hardcoded crafting recipes, this game uses freeform AI-powered crafting. Items have skills/quirks that can be used on other items, and the AI calculates realistic outcomes. There's no required schema for item metadata - items can theoretically have any semantically meaningful properties.

### Scale Optimization

The game improves with more players:
1. **Item Pool** - Discarded items go into a shared pool, so new players can pull previously-minted items instantly instead of waiting 10+ seconds for AI generation
2. **Vector Matching** - Item images are matched by vector embeddings of descriptions. Similar items reuse existing images, reducing generation costs and wait times as the database grows
